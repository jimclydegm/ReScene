# Reference environments — October 30, 2026

## Problem and implementation

The reported living room was analyzed as three walls, but `surface-understanding-v2` could encode only one seam. Its material path produced one very large wall, a generic floor tile and no window. A successful image call was not proof of a complete room.

The default **Reference** construction mode now uses a dedicated environment observation and render contract. It does not force every photo into a room. Existing Materials and Photo choices remain available.

1. **Plan before reconstruction.** Muse Spark returns `environment-observation-v1`, scoped to the normalized photo: ordered polygons for each visible floor, wall, ceiling, broad surface and structural trim; parent-linked windows/doors/openings; visible wall count; intrinsic color/material/roughness; confidence and lighting effects. Shared corners use the same source coordinates. Shadows, light bands and material borders are not architectural creases. A smooth studio sweep is distinct from a room. Hidden walls and ceilings are not invented.
2. **Shared depth evidence.** Room and textured planar environments use Meta VGGT through `fal-ai/vggt-1b`, with one image, `export_prediction_data:true`, no exported point cloud and no depth PNG. Decode float32 depth/confidence and intrinsics. The host pads to 518 square after rounding the short side to a multiple of 14; source coordinates explicitly remove that padding. Provider input images and redundant arrays are discarded from the stored prediction. This is depth evidence, not a ready-to-render room mesh.
3. **Construct surfaces in the saved frame.** Reproject depth through the existing reference camera. A robust common scale uses visible ground and the saved floor height, excluding foreground masks. RANSAC fits background planes, constraining architectural walls to vertical. Observed floor contacts, including contacts below baseboards, anchor walls. Thin trim inherits its adjacent wall plane. Shared corners solve incident planes together. Triangulation cuts opening holes; an inset photo card retains the view through each opening. The floor remains **one continuous opaque plane**, with no second shadow receiver. Observed walls continue beyond cropped borders; their outside faces cut away during orbit. No floor object mesh, fabricated tabletop edge or universal room box.
4. **Recover intrinsic appearance.** One Muse Image edit receives the source plus a foreground-removal guide. It removes objects, their shadows and directional illumination while preserving perspective and materials. Plain surfaces receive uniform color. Textured surfaces retain bounded source detail outside a dilated foreground footprint; generated detail fills occlusion. Low-frequency illumination is removed from both fields. Visible window context remains photograph-derived. A reference projection covers observed pixels; a plane-coordinate material patch continues texture beyond the image crop rather than fading to a visible plain rectangle. PBR materials respond to the existing lights.
5. **Review and preserve state.** Check expected/built walls, visible background coverage, depth plane evidence and corner reprojection disagreement. Missing walls, less than 80% coverage or more than 8% corner disagreement keeps the saved background; less than 94% coverage or more than 2.5% disagreement adds review notes. A private Spark image review checks the empty atlas, structural differences and remaining illumination. Remaining foreground rejects it. Atlas appearance/structure disagreements stay visible as PARTIAL review notes: the atlas is not a full rendered-scene comparison. They never silently become an accuracy certificate. Keep a previous-background swap. Object meshes, products, replacements, transforms, camera and light edits remain unchanged.

## Workflows, storage and safety

- `generateScene` plans structure before initial object submission. After mesh/appearance work, deterministic background workflow helpers prepare depth, poll the saved job in yielding steps, then build the environment. Paid steps have zero automatic retries. Poll/result retrieval can retry without another submission.
- Cache completed depth by scene + normalized photo. Reuse unfinished known same-photo jobs across requests; never submit the same paid job just because a poll or workflow was interrupted. Resume uses the saved request, source ID and background-entry scene revision. No request ID means uncertain submission, not permission to retry.
- Existing active-run, archive, expiry, owner/origin, revision and idempotency guards remain. Store completed provider responses privately before applying live state. Canceled/stale work cannot replace the visible background. Commit the derived albedo and numeric render plan atomically with a revision increment.
- Layout matching rebuilds numeric geometry from saved depth/observations without inference if its common frame changes. Undo restores the associated stage/background plan. Background restore swaps previous render assets/plans without touching products or objects.
- No SQL migration or new account/key is needed. Prisma `Scene.settings` holds the private observation/review and background history; `Scene.stage.background` holds validated render geometry. GenerationSteps retain analysis/depth/albedo/review lineage; private Asset rows retain predictions and raw image responses. The one approved empty albedo is `SURFACE_TEXTURE`.
- Public snapshot v2 freezes numeric surfaces/material settings and an exact same-scene READY albedo allowlist. It does not publish source photos, masks, prompts, raw predictions, private analysis/review or provider IDs. Its existing single background texture field is reused. Manifests are capped/read at 256 KiB. Published old snapshots keep their original interpretation and assets.

## Verified evidence and limits

Private evidence is ignored under `test-results/environment`. The reported photo produced three walls, floor, structural trim and a window opening, with 100% planned visible-background coverage and 0.76% maximum corner disagreement. One depth job, one Muse image and two Spark calls were used; the object models were not regenerated. The image reviewer flagged window/baseboard/material differences; those notes remain. Native Chrome checks cover actual WebGL, texture continuation, orbit/Zoom lock, Day/Night preview and narrow framing; production desktop/390×844 method/report controls also pass. The reported scene is now revision9, with unchanged objects/products/camera/lights. Same-scene snapshot privacy/allowlisting and background restore pass, and disposable QA is restored. These are not proof of exact background reconstruction.

Single-image depth has unknown scale and uncertain hidden geometry. The saved camera can disagree with architectural vanishing points; large disagreements are reported or rejected. A window is an inset photograph, not recovered exterior geometry; changing indoor lighting does not synthesize a night exterior. Visible material detail and generated hidden texture remain approximate, and this path does not recover physically measured PBR maps. Complex nonplanar scenery retains the photo path, continuous studio sweeps retain the cove path, and plain fields stay plain.
